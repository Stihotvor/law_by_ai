    T2: src/core/llm errors, port and config resolver¶

    Context¶

    The client needs error types, a port for fakes and a resolver that builds one frozen config per agent. This keeps config a leaf module and lets agent tests use a fake ChatModel. It serves the Edge Cases and Failure Modes of requirements.md.

    Technical Approach¶

    Path 2 of decision.md. New package src/core/llm/. __init__.py stays empty of public names except as needed by T3.

    errors.py: - class LLMError(Exception) with __init__(self, message: str, status_code: int | None = None). It keeps status_code as an attribute. - class LLMTimeoutError(LLMError). - class LLMConfigError(Exception). Its base is Exception, not LLMError.

    ports.py: - class ChatModel(Protocol) with def chat(self, agent_name: str, messages: list[dict[str, str]]) -> str: .... - The Protocol method body ... carries # pragma: no cover, because no code runs it and T3 needs 100 % coverage of src/core/llm.

    config.py: - LLM_AGENTS: tuple[str, ...] = document_fetcher, document_processor, legal_research, change_tracker, knowledge_graph, analysis, bureaucracy_assistant. - @dataclass(frozen=True) class AgentLLMConfig with fields base_url: str, model: str, timeout: float, api_key: str. - def resolve(settings: Settings, agent_name: str) -> AgentLLMConfig: - Unknown agent: LLMConfigError, message contains the agent name. - Values come from settings.llm_setting for base_url, model, timeout, api_key. The timeout falls back to settings.llm_timeout. - Empty model: LLMConfigError, message contains the agent name and the variable LLM_MODEL_<AGENT>. - Bad per-agent timeout (not a positive finite number): ValueError, message contains LLM_TIMEOUT_<AGENT>. - Base URL with credentials, a query, a fragment, or a scheme other than http/https: LLMConfigError, message contains the agent name. The message holds no URL. - Order of checks is not fixed by the decision.

    Tests: tests/unit/core/llm/test_errors.py, test_config.py. A test compares LLM_AGENTS with the set of llm_model_* properties found on Settings by dir. A test file defines a fake class and assigns it to a ChatModel variable, so pyright checks it.

    Decided (default kept): Is an empty base URL (no per-agent and no global value) an LLMConfigError? The decision names only the URL checks. Default in this spec: yes, same error, names the agent. Decided (default kept): Exact message texts are not in decision.md. Only the rule "names the agent" and "names the variable" is fixed.

    Acceptance Criteria¶

    Scenario: Error hierarchy
  Given the three error classes
  Then LLMTimeoutError is a subclass of LLMError
  And LLMConfigError is not a subclass of LLMError
  And LLMError("x", 503).status_code equals 503
  And LLMError("x").status_code is None

Scenario: LLM_AGENTS matches Settings
  Given the Settings class
  Then LLM_AGENTS equals the set of names behind the seven llm_model_* properties

Scenario: A per-agent value wins
  Given LLM_BASE_URL_BUREAUCRACY_ASSISTANT is "http://a:1/v1" and LLM_BASE_URL is "http://g:2/v1"
  And LLM_MODEL_BUREAUCRACY_ASSISTANT is "m-a" and LLM_TIMEOUT_BUREAUCRACY_ASSISTANT is "5"
  And LLM_API_KEY_BUREAUCRACY_ASSISTANT is "k-a"
  When the code calls resolve(settings, "bureaucracy_assistant")
  Then the config is base_url "http://a:1/v1", model "m-a", timeout 5.0, api_key "k-a"

Scenario: The global value is the fallback
  Given only LLM_BASE_URL, LLM_MODEL, LLM_TIMEOUT and LLM_API_KEY are set
  When the code calls resolve(settings, "document_processor")
  Then each config field equals the global value

Scenario: Unknown agent
  When the code calls resolve(settings, "nope")
  Then LLMConfigError is raised
  And the message contains "nope"

Scenario: No model
  Given no model variable is set for document_processor
  When the code calls resolve(settings, "document_processor")
  Then LLMConfigError is raised
  And the message contains "document_processor" and "LLM_MODEL_DOCUMENT_PROCESSOR"

Scenario: Bad per-agent timeout
  Given LLM_TIMEOUT_BUREAUCRACY_ASSISTANT is "0"
  When the code calls resolve(settings, "bureaucracy_assistant")
  Then ValueError is raised
  And the message contains "LLM_TIMEOUT_BUREAUCRACY_ASSISTANT"

Scenario Outline: Bad base URL
  Given the base URL for bureaucracy_assistant is <url>
  When the code calls resolve(settings, "bureaucracy_assistant")
  Then LLMConfigError is raised
  And the message contains "bureaucracy_assistant"
  And the message does not contain the URL
  Examples:
    | url                      |
    | http://user:pw@host/v1   |
    | http://host/v1?x=1       |
    | http://host/v1#frag      |
    | ftp://host/v1            |

Scenario: A fake satisfies the port
  Given a class with chat(agent_name, messages) -> str
  When it is assigned to a ChatModel variable
  Then pyright reports no error

    Definition of Done¶

    • The task's done_when check passes.
    • Tests exist for every scenario and pass.
    • The quality gate reports pass or skipped (never fail).
    • No OPEN: item remains.
