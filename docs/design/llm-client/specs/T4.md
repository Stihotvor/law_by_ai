# T4: Quality gate on the whole change

## Context
The project gate must pass before the change is done. This task runs it on T1 to T3 together. It serves the Success Metrics of `requirements.md`.

## Technical Approach
No file changes. Run from the repo root with the `.venv` tools:
- `.venv/bin/ruff check`
- `.venv/bin/ruff format --check`
- `.venv/bin/pyright`
- `.venv/bin/pytest -m "not integration"`
- `diff-cover` as in the "Coverage and mutation gates" section of CONTRIBUTING.md.

If a tool is missing in `.venv`, report it and skip that check. Do not install a tool. If a check fails, report the failure to the owner of the file. Do not fix code in this task.

## Acceptance Criteria
```gherkin
Scenario: The gate passes
  Given T1, T2 and T3 are done
  When the five gate commands run
  Then ruff check, ruff format --check, pyright and pytest all exit 0
  And diff-cover meets the CONTRIBUTING.md gate

Scenario: A check fails
  Given one gate command exits non-zero
  When the gate task ends
  Then the report names the command and the first error
  And the task is not marked done
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
