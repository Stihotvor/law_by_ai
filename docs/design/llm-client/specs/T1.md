# T1: Settings llm_setting and llm_timeout

## Context
The LLM client needs a per-agent value with a global fallback for base URL, model, timeout and API key. Settings has `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` and seven `LLM_MODEL_<AGENT>` properties. It has no timeout and no generic lookup. This task adds both. It serves the "Per agent" constraint and the timeout edge case of `requirements.md`.

## Technical Approach
Path 2 of `decision.md`: Settings gets only a generic lookup. In `src/config/settings.py`:
- Add method `llm_setting(self, field: str, agent: str) -> str`. It reads `LLM_<FIELD>_<AGENT>` (field and agent upper-cased), then `LLM_<FIELD>`. A set non-empty value wins. It returns `""` when both are unset or empty.
- Add property `llm_timeout -> float`. Key `LLM_TIMEOUT`, default `60.0`. Surrounding whitespace is stripped. An empty value gives the default. A non-number, `nan`, `inf`, zero or a negative value raises `ValueError`. The message contains `LLM_TIMEOUT`.
- Keep the seven `llm_model_*` properties, `llm_model`, `llm_base_url` and `llm_api_key` unchanged.
- Settings raises only `ValueError`. It does not import from `src/core`.

In `tests/unit/config/test_settings.py`: add the keys `LLM_TIMEOUT`, `LLM_BASE_URL_BUREAUCRACY_ASSISTANT` and the other keys the new tests use to `_ENV_KEYS`. Add one case per scenario below.

Decided (default kept): Does `llm_setting` strip whitespace from string values (model, URL, key)? The decision names no rule. Default in this spec is no strip.

## Acceptance Criteria
```gherkin
Scenario: The per-agent value wins over the global value
  Given LLM_MODEL is "global-m" and LLM_MODEL_BUREAUCRACY_ASSISTANT is "agent-m"
  When the code calls llm_setting("model", "bureaucracy_assistant")
  Then the result is "agent-m"

Scenario: The global value is the fallback
  Given LLM_MODEL is "global-m" and LLM_MODEL_DOCUMENT_PROCESSOR is not set
  When the code calls llm_setting("model", "document_processor")
  Then the result is "global-m"

Scenario: Both values unset
  Given LLM_API_KEY and LLM_API_KEY_DOCUMENT_PROCESSOR are not set
  When the code calls llm_setting("api_key", "document_processor")
  Then the result is the empty string

Scenario: The timeout has a default
  Given LLM_TIMEOUT is not set
  When the code reads llm_timeout
  Then the value is 60.0

Scenario: The timeout accepts a padded number
  Given LLM_TIMEOUT is " 0.2 "
  When the code reads llm_timeout
  Then the value is 0.2

Scenario Outline: The timeout rejects a bad value
  Given LLM_TIMEOUT is <value>
  When the code reads llm_timeout
  Then a ValueError is raised
  And the error message contains "LLM_TIMEOUT"
  Examples:
    | value |
    | abc   |
    | 0     |
    | -1    |
    | nan   |
    | inf   |

Scenario: Existing model properties are unchanged
  Given LLM_MODEL_BUREAUCRACY_ASSISTANT is "m1"
  When the code reads llm_model_bureaucracy_assistant
  Then the value is "m1"
```
