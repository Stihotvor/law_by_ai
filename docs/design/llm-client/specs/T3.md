# T3: LLMClient.chat over httpx

## Context
Agents have no way to call a model today. This task adds the one shared client for an OpenAI-compatible server. It serves the Business Goals, Failure Modes and Success Metrics of `requirements.md`.

## Technical Approach
Path 2 of `decision.md`. In `src/core/llm/client.py`:
- `class LLMClient` is the only public name. `__init__(self, settings: Settings, *, transport: httpx.BaseTransport | None = None)`. `chat(self, agent_name: str, messages: list[dict[str, str]]) -> str`. It satisfies `ChatModel`.
- `chat` order: empty `messages` raises `ValueError`. Then `resolve(settings, agent_name)` (raises `LLMConfigError` for an unknown agent, no model or a bad URL). No request is sent before these pass.
- Request: `POST {base_url.rstrip("/")}/chat/completions`, JSON body `{"model": model, "messages": messages}`. Header `Authorization: Bearer <key>` only when the key is not empty.
- Follow the Mistral OCR adapter (`src/agents/fetch/ocr/mistral.py`): `follow_redirects=False`, `trust_env=False`, injectable transport, no logging.
- Pass `httpx.Timeout(timeout / 4)` to the request. Stream the body. Cap it at 1 MiB (1048576 bytes). Use a monotonic deadline checked before each read and after each chunk.
- Error mapping:
  - Deadline or httpx timeout: `LLMTimeoutError`, within 1.25 × timeout + 1 s. Each httpx phase gets `timeout / 4`.
  - Body over 1 MiB: `LLMError`.
  - Status not 2xx: `LLMError` with `status_code`.
  - Other `httpx` transport error: `LLMError` with `status_code=None`.
  - Non-JSON body, no `choices`, or non-string `choices[0].message.content`: `LLMError` with `status_code=200`.
- Error text holds no API key, no message content and no base URL.
- Answer: `choices[0].message.content`.

Tests in `tests/unit/core/llm/test_client.py` use `httpx.MockTransport`. The timeout test uses 0.2 s and checks elapsed time under 1.25 s. A second test stalls after one chunk (read timeout from `request.extensions["timeout"]["read"]`) and checks the same bound and that the read timeout is `timeout / 4`. Coverage of `src/core/llm/` is 100 %.

Decided (default kept): Exact error message texts are not in `decision.md`. Tests assert type, `status_code` and absence of secrets, not full text.
Decided (default kept): A body that is invalid JSON with a non-2xx status: status error wins (default in this spec).

## Acceptance Criteria
```gherkin
Scenario: bureaucracy_assistant gets an answer
  Given LLM_BASE_URL is "http://llm.test/v1/" and LLM_MODEL_BUREAUCRACY_ASSISTANT is "m1"
  And the server answers 200 with choices[0].message.content "hello"
  When the code calls chat("bureaucracy_assistant", [{"role": "user", "content": "hi"}])
  Then the result is "hello"
  And the request was POST to "http://llm.test/v1/chat/completions"
  And the body is {"model": "m1", "messages": [{"role": "user", "content": "hi"}]}

Scenario: document_processor uses its own model and key
  Given LLM_MODEL_DOCUMENT_PROCESSOR is "m2" and LLM_API_KEY_DOCUMENT_PROCESSOR is "k2"
  When the code calls chat("document_processor", one message)
  Then the request body model is "m2"
  And the Authorization header is "Bearer k2"

Scenario: Empty key sends no Authorization header
  Given the API key for bureaucracy_assistant is empty
  When the code calls chat("bureaucracy_assistant", one message)
  Then the request has no Authorization header

Scenario: Unknown agent
  When the code calls chat("nope", one message)
  Then LLMConfigError is raised
  And the message contains "nope"
  And no request was sent

Scenario: Empty messages
  When the code calls chat("bureaucracy_assistant", [])
  Then ValueError is raised
  And no request was sent

Scenario: Slow server
  Given LLM_TIMEOUT is "0.2" and the server waits longer
  When the code calls chat("bureaucracy_assistant", one message)
  Then LLMTimeoutError is raised
  And it is a subclass of LLMError
  And the call took less than 1.25 seconds

Scenario: Body over 1 MiB
  Given the server answers 200 with a body of 1048577 bytes
  When the code calls chat("bureaucracy_assistant", one message)
  Then LLMError is raised

Scenario Outline: HTTP and transport failures
  Given the server <behavior>
  When the code calls chat("bureaucracy_assistant", one message)
  Then LLMError is raised
  And status_code equals <status>
  Examples:
    | behavior                    | status |
    | answers 500                 | 500    |
    | answers 401                 | 401    |
    | refuses the connection      | None   |
    | answers 200 with no choices | 200    |
    | answers 200 with content 5  | 200    |
    | answers 200 with body "x"   | 200    |

Scenario: Redirect is not followed
  Given the server answers 302
  When the code calls chat("bureaucracy_assistant", one message)
  Then LLMError is raised with status_code 302
  And no second request was sent

Scenario: No secret in error text
  Given the API key is "sekret-key", the base URL is "http://llm.test/v1" and the message content is "private-text"
  When any failure above is raised
  Then str(error) contains none of "sekret-key", "llm.test" and "private-text"

Scenario: Full coverage
  When pytest runs tests/unit/core/llm with --cov=src/core/llm --cov-fail-under=100
  Then it exits 0
```
