# T7 Integration fixtures as lawbyai_app

## Context
Integration tests connect with the configured URL, which was the superuser. They must now run as `lawbyai_app`, and use the owner only to set up and clean data. Several tests use `set_config('app.current_tenant', '', true)` to see all rows. That no longer works. It serves the metric "all Docker integration tests pass as lawbyai_app".

## Technical Approach
- `tests/integration/conftest.py`: keep `postgres_url` (line 27, app URL). Add a fixture `owner_url` from `postgres_owner_url` (T2) that skips when unreachable. Add a helper that runs SQL as the owner inside a tenant context. The owner setup statements set `app.current_tenant` to the test tenant in each transaction, because the policies fail closed and FORCE on `tenants` and `users` binds the owner too.
- `tests/integration/test_users_login_store.py`: the `store` fixture cleanup (lines 60-71) and `_all_tenants` (line 44) use an empty tenant. Replace with the tenant `TEST_TENANT` (line 56). The `INSERT_USER` statement (line 38) uses tenant `'t'`: set `app.current_tenant` to `t`.
- Scratch database fixture (`scratch_url`, line 158): build a test-only superuser URL from `POSTGRES_USER` and `POSTGRES_PASSWORD`. Use it only for `CREATE DATABASE` and `DROP DATABASE`. Migrate the scratch database with the owner URL (`command.upgrade` and `command.downgrade`). Run assertions as `lawbyai_app`. The owner gets no CREATEDB. Roles are cluster-wide, so they exist in the scratch database. The per-database grants come from the migration.
- The migration tests (`test_migration_refuses_case_duplicate_emails`, `test_migration_normalises_existing_emails`, session version tests) insert and read users with no tenant. Rework them to set a tenant, using the owner connection.
- `tests/integration/test_login_flow.py`: `_sql` (line 47) sets an empty tenant. Use `TENANT` (line 23) instead. The `UPDATE users` calls run as the owner and set `app.current_tenant` to `TENANT` in each statement, because FORCE applies to the owner too.
- `tests/integration/test_init_stack.py`: the `settings` fixture cleanup (lines 50-53) deletes with no tenant. Set the init tenant for the user delete and the tenant delete. `_count` (line 57) needs the tenant for `users` and `tenants`. The final `get_user_by_email` (line 82) runs with no tenant and returns `None`: use `get_login_user` or `tenant_context`.
- `FakeSettings` in `tests/factories/bootstrap.py` carries the owner URL, because `ensure_schema` (T6) uses it.
