# T5 Docs SQL for old volumes

## Context
The init script runs on fresh volumes only. Old volumes have one superuser role that owns everything, and the new migration stops there. This task gives the SQL that moves an old volume to the new model. It serves the failure mode "old volume without the new roles".

## Technical Approach
- Edit `docs/migrations.md`. Add one SQL block that mirrors `docker/initdb/00-roles.sh` from T1: the three roles, `GRANT CREATE, USAGE ON SCHEMA public` for the owner, `GRANT USAGE ON SCHEMA public` for `lawbyai_auth`, and `GRANT lawbyai_auth TO lawbyai_owner WITH INHERIT FALSE, SET TRUE`.
- Add per-object `ALTER TABLE ... OWNER TO lawbyai_owner` for `tenants`, `users`, `legal_document`, `rejected_document`, `alembic_version`. Add `ALTER SEQUENCE ... OWNER TO` for the `rejected_document` id sequence and `ALTER FUNCTION users_bump_session_version() OWNER TO lawbyai_owner`.
- State that `REASSIGN OWNED` cannot be used, because the old role is the bootstrap superuser.
- Use placeholders for the passwords and tell the reader to take them from env.
- Do not link to other docs (project rule: no cross-doc links).
- The section must tell the reader to run the block as the bootstrap superuser before `alembic upgrade head` with the owner URL.

## Acceptance Criteria

```gherkin
  Given docs/migrations.md

  Given docs/migrations.md and docker/initdb/00-roles.sh
  When a test compares the role attributes and grants
  Then both lists are equal

Scenario: Docs build
  Given the edited docs
  When mkdocs build --strict runs
  Then it exits 0
```
