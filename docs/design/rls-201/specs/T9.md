# T9 Full quality gate and coverage check

## Context
The repo rule says no task is done before ruff, pyright and pytest pass. This task runs the whole gate on the combined change. It serves the metric "diff-cover is 90% or more" and "all Docker integration tests pass as lawbyai_app".

## Technical Approach
- No file changes (`files` is empty). Report the result of each command. Fix findings by sending them back to the task that owns the file. Do not relax any check.
- Run from the repo root with the `.venv` tools: `ruff check`, `ruff format --check`, `pyright`, `pytest -m "not integration"`.
- Run the Docker test service: `docker compose --profile test -f docker/docker-compose.yml run --rm test`, after `build test` so the image holds the new code. It needs `docker/.env` with the new password variables `LAWBYAI_OWNER_PASSWORD` and `LAWBYAI_APP_PASSWORD` (T1, T2).
- Run diff-cover against `main` with the exact commands of the "Coverage and mutation gates" section of CONTRIBUTING.md. CONTRIBUTING.md has no command that builds the coverage XML from the Docker run. The diff-cover input is the XML of the unit run:

  ```bash
  PYTHONPATH=src uv run pytest -m "not integration" --cov --cov-branch --cov-report=xml --cov-report=term-missing
  uv run diff-cover coverage.xml --compare-branch=origin/main --fail-under=90
  ```

  Do not invent a Docker coverage command. The gate is 90% or more.
- Mutation testing runs in CI only. Do not run it here.

## Acceptance Criteria
```gherkin
Scenario: Static checks pass
  Given the merged change
  When ruff check, ruff format --check and pyright run
  Then each exits 0

Scenario: Unit tests pass
  Given the merged change
  When pytest -m "not integration" runs
  Then it exits 0

Scenario: Docker suite passes as the app role
  Given a fresh volume and docker/.env with the new variables
  When the Docker test service runs
  Then all tests pass

Scenario: Coverage gate
  Given the coverage.xml from the CONTRIBUTING.md pytest command
  When the CONTRIBUTING.md diff-cover command runs against main
  Then it reports 90% or more
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
