# T2 Owner URL, env.py, compose, initialize() head check

## Context
Migrations must run as `lawbyai_owner`. The app, worker and tests run as `lawbyai_app`, which cannot migrate. This task splits the two URLs and makes `initialize()` check the schema only. It serves the constraints on roles and the success metric that all app connections have `rolsuper = false`.

## Technical Approach
- `src/config/settings.py`: settings build the app URL (user `lawbyai_app`, password `LAWBYAI_APP_PASSWORD`) and a new property `postgres_owner_url` (user `lawbyai_owner`, password `LAWBYAI_OWNER_PASSWORD`) beside `postgres_url` (line 147). Quote the user and password as `postgres_url` does. `POSTGRES_URL` and `POSTGRES_OWNER_URL` override the built URLs when set. Role names are fixed in code. Update the table in the module docstring (lines 9-64).
- `POSTGRES_USER` and `POSTGRES_PASSWORD` stay the bootstrap superuser. Only the `postgres` service and the init script use them. No other service receives them, except the test-only scratch fixture (T7).
- `migrations/env.py`: line 25 uses `get_settings().postgres_url`. Change it to the owner URL. Update the docstring.
- `src/plugins/relational_db/postgres.py`: in `PostgreSQLStore.initialize()` (line 154) remove the `_upgrade_schema()` call. Delete `_upgrade_schema` (lines 113-128) or move it for the test and init use. After the engine is created, read the Alembic head from the script directory and the current revision from the DB (`MigrationContext.configure(conn).get_current_revision()`). Raise a clear error (new exception class, message names the current and the head revision) if they differ. Do not run upgrade. The app role needs SELECT on `alembic_version` (T4).
- `docker/docker-compose.yml`: pass `LAWBYAI_OWNER_PASSWORD` only to services that migrate. Pass `LAWBYAI_APP_PASSWORD` to `app`, `celery-worker`, `init` and `test`. Change `init` (line 133): run `alembic upgrade head` with the owner URL, then `python -m bootstrap` with the app URL. The `test` service (line 265): run `alembic upgrade head` with the owner URL before `pytest` (line 296). Do not give the owner secret to `app` and `celery-worker`.
- Unit tests in `tests/unit/` (names must match `-k 'settings or initialize_head'`).

## Acceptance Criteria
```gherkin
Scenario: Owner URL comes from env
  Given LAWBYAI_OWNER_PASSWORD and LAWBYAI_APP_PASSWORD are set in env
  When Settings.postgres_owner_url is read
  Then it holds the user lawbyai_owner, URL-quoted, and differs from postgres_url
  And postgres_url holds the user lawbyai_app

Scenario: URL override wins
  Given POSTGRES_OWNER_URL and POSTGRES_URL are set in env
  When Settings.postgres_owner_url and postgres_url are read
  Then each equals its override value

Scenario: Alembic uses the owner URL
  Given the owner variables are set
  When migrations/env.py runs
  Then the Alembic sqlalchemy.url equals postgres_owner_url

Scenario: initialize() fails on a database not at head
  Given a database one revision behind head
  When PostgreSQLStore.initialize() runs
  Then it raises an error whose message names the current and head revision
  And no schema object has changed

Scenario: initialize() passes at head
  Given a database at head
  When PostgreSQLStore.initialize() runs
  Then it returns and the store accepts calls

Scenario: Compose migrates with the owner
  Given the compose file
  When a test parses the init and test services
  Then each runs alembic upgrade head with the owner URL before its main command
```
