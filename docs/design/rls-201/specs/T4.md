# T4 Migration part 2: auth_lookup_user, grants, downgrade

## Context
Login must read one user across tenants before a tenant is known. After T3 the policies block that read. This task adds the only cross-tenant read, a SECURITY DEFINER function, and the grants for the app role. It serves the metrics on `pg_proc` and PUBLIC EXECUTE.

## Technical Approach
- Same revision file as T3, in `migrations/versions/`.
- Step 5: `CREATE FUNCTION public.auth_lookup_user(p_email text) RETURNS TABLE (id varchar, tenant_id varchar, email varchar, role varchar, name varchar, is_active boolean, password_hash varchar, session_version integer)`. Use LANGUAGE sql, STABLE, STRICT, SECURITY DEFINER, `SET search_path = pg_catalog, pg_temp`. Body: `SELECT ... FROM public.users u WHERE u.email = lower(btrim(p_email))`. Column types must match `User` in `src/plugins/relational_db/postgres.py` (lines 74-86). Then `REVOKE EXECUTE ... FROM PUBLIC` and `GRANT EXECUTE ... TO lawbyai_app`, and only after that `ALTER FUNCTION ... OWNER TO lawbyai_auth` (the ACL moves with the owner). The downgrade drops the function under `SET LOCAL ROLE lawbyai_auth`, then `RESET ROLE`.
- This migration grants `lawbyai_auth` column SELECT on `users` (id, tenant_id, email, role, name, is_active, password_hash, session_version). The init script does not grant it (T1).
- Step 6: `GRANT SELECT, INSERT, UPDATE, DELETE` on `tenants`, `users`, `legal_document`, `rejected_document` to `lawbyai_app`. `GRANT USAGE, SELECT` on the `rejected_document` id sequence. `GRANT SELECT ON alembic_version`. `ALTER DEFAULT PRIVILEGES FOR ROLE lawbyai_owner REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC`.
- Step 7, `downgrade()`: drop the function, revoke the grants (including the `lawbyai_auth` column SELECT), restore the old policies with `ALTER POLICY` exactly as `4439761c5e40` defines them, undo the default privileges revoke. Keep `ck_users_email_normalised`. FORCE: `4439761c5e40` sets FORCE only on `tenants` and `users`. The downgrade leaves FORCE on those two tables as it was, and sets none on `legal_document` or `rejected_document`.
- The existing test `test_downgrade_removes_objects_and_keeps_lowercase_emails` uses `PREVIOUS_REVISION = "963e40b83003"` and must still pass.
