# T3 Migration part 1: role checks, NO FORCE window, tenant-only policies

## Context
The policies on `users` and `tenants` show every row when `app.current_tenant = ''`, so a missing tenant leaks all data. This revision checks the roles, then closes that gap so no tenant means zero rows. It serves the metrics "0 rows with no tenant set" and "tenant A cannot write tenant B".

## Technical Approach
- New file in `migrations/versions/`, `down_revision = "77985ac8fa22"`. T4 adds its steps to the same revision file. The two tasks share one revision, so T4 starts after T3 is merged.
- First statement: `SET LOCAL lock_timeout = '5s'`.
- Step 1, checks: query `pg_roles` for the three roles. Query `pg_class` and `pg_proc` owners for `tenants`, `users`, `legal_document`, `rejected_document`, `alembic_version` and the function `users_bump_session_version`. Raise `RuntimeError` naming each missing role or wrong owner. The four-table list in decision.md is the ownership check only.
- Step 2, NO FORCE window: `ALTER TABLE ... NO FORCE ROW LEVEL SECURITY` on `tenants` and `users`, do every data read of this revision, then `ALTER TABLE ... FORCE ROW LEVEL SECURITY` on the same two tables in the same transaction.
- Step 4: `ALTER POLICY` with the existing names (read them from `4439761c5e40`) to `tenant_id = nullif(current_setting('app.current_tenant', true), '')` for USING and WITH CHECK. On `tenants` use `id`.
- FORCE stays as migration `4439761c5e40` set it (lines 58 and 69): on `tenants` and `users` only. `legal_document` and `rejected_document` get no RLS and no FORCE. Do not change that.
- The downgrade is in T4.

## Acceptance Criteria
```gherkin
Scenario: Missing role stops the migration
  Given a database where lawbyai_auth does not exist
  When alembic upgrade head runs with the owner URL
  Then it fails with an error that names lawbyai_auth
  And no policy has changed

Scenario: Wrong owner stops the migration
  Given tenants is owned by another role
  When alembic upgrade head runs
  Then it fails with an error that names tenants and lawbyai_owner

Scenario: No tenant means zero rows
  Given rows in users and tenants for two tenants
  When lawbyai_app runs SELECT count(*) FROM users and FROM tenants with no tenant set
  Then both counts are 0

Scenario: Tenant isolation on read and write
  Given app.current_tenant is set to A
  When lawbyai_app selects from users
  Then only tenant A rows return
  And an INSERT of a tenant B row fails the WITH CHECK

Scenario: FORCE is on at head for tenants and users only
  Given the migration ran
  When the query reads pg_class.relforcerowsecurity for the four tables
  Then the value is true for tenants and users
  And the value is false for legal_document and rejected_document

Scenario: Lock timeout is set
  Given the revision file
  When a test reads its text
  Then it contains SET LOCAL lock_timeout = '5s'
```
