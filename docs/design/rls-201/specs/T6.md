# T6 get_login_user calls the function; bootstrap in tenant context

## Context
After the migration the app role cannot read `users` without a tenant. Login must call `auth_lookup_user`. The bootstrap must work with tenant scoping. It serves the metric "auth_lookup_user returns exactly 1 row with no tenant set" and the constraint that `get_login_user` keeps its signature.

## Technical Approach
- `src/plugins/relational_db/postgres.py`, `get_login_user` (line 379): replace the ORM select and `without_tenant()` with `SELECT * FROM auth_lookup_user(:email)` and the existing `_login_user_to_dict` shape (line 467), with the same dict keys (`id, tenant_id, email, role, name, is_active, password_hash, session_version`). Pass `email.strip().lower()` or the raw value, as the function normalises. Return `None` on zero rows. `OperationalError` still propagates. Remove the unused `without_tenant` import (line 33) if no other use remains.
- `get_user_by_email` (line 371): docstring states it returns `None` with no tenant set.
- Module docstring (lines 15-19): the text "When the setting is empty ... fully visible" is wrong. Replace with fail-closed text. Update the `TENANT_SETTING` comment (line 49, "Empty string == no tenant scoping").
- `list_tenants` (line 411): docstring states it returns the current tenant only.
- `src/bootstrap/init_stack.py`: `ensure_tenant` (line 224) and `ensure_admin` (line 235) run inside `tenant_context(settings.init_tenant_id)` from `core.security`. The tenant row does not need to exist before the context: `create_tenant` inserts a row whose `id` equals the setting, so WITH CHECK passes. `ensure_admin` finds the admin through `get_login_user`, not `get_user_by_email`. Update the `Store` Protocol (line 116) with `get_login_user`.
- `ensure_tenant` under the `INIT_TENANT_ID` context is the idempotent path. On the first run `list_tenants` returns empty (current tenant only) and `create_tenant` runs. On a rerun `IntegrityError` is caught.
- `ensure_schema` (line 204) runs `alembic upgrade` with the owner URL (`postgres_owner_url`, T2). It then calls `store.initialize()`, which only checks head after T2, and compares revisions. Update its docstring (line 205 "Apply the database migrations") and the module docstring.
- `db_revision(url)` (line 194) and `run` (line 297) use `settings.postgres_url`: the app URL. The app role has SELECT on `alembic_version` (T4), so no change is needed there.
