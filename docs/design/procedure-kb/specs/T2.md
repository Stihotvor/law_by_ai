# T2: Repository port and ProcedureService with fake repository

## Context
The service is the one entry point for the seed script, the later upload page and the assistant. It enforces the admin rule before any database work. It serves the admin-write, identical-content and not-found rules in requirements.md.

## Technical Approach
Add to `src/core/procedures/` (imports only `core.security` and its own modules, no SQL):
- `ports.py`: `ProcedureRepository` Protocol with `save(procedure, actor) -> ImportResult`, `get(slug) -> Procedure | None`, `list() -> list[ProcedureSummary]`.
- `service.py`: `ProcedureService(repository)`.
  - `import_procedure(text) -> ImportResult`: call `require_admin_principal()` first, before any session opens. Take the actor from the principal. Parse with `parse_procedure_yaml`, then call `repository.save`.
  - `get_procedure(slug) -> Procedure | None`: `None` for not found and for a malformed slug (check the slug pattern before the repository call).
  - `list_procedures() -> list[ProcedureSummary]`, sorted by slug.
  - Errors: `ProcedureValidationError` for bad input, `PrincipalRequiredError` for a non-admin, `ProcedureStoreError` for a store failure. Chain the cause. The message holds no content.
- Tests in `tests/unit/core/procedures/test_procedure_service.py` use an in-memory fake repository that follows the port.
- Checked: `require_admin_principal`, `RequestPrincipal` and `principal_context` exist in `core/security/principal.py`. Import them from there if `core.security` does not export them.

## Acceptance Criteria
Scenario: non-admin import
  Given a principal with role `user`
  When `import_procedure(text)` runs
  Then `PrincipalRequiredError` is raised and the fake repository got no `save` call

Scenario: admin import
  Given an admin principal with email "a@x.org" and valid YAML
  When `import_procedure(text)` runs
  Then `save` is called once with actor "a@x.org" and the result is returned

Scenario: identical content
  Given the fake repository returns `changed=False`
  When `import_procedure(text)` runs
  Then the result has `changed=False`

Scenario: bad input writes nothing
  Given an admin principal and YAML with an empty `source_url`
  When `import_procedure(text)` runs
  Then `ProcedureValidationError` is raised and `save` was not called

Scenario: unknown or malformed slug
  Given the repository has no slug "nope"
  When `get_procedure("nope")` and `get_procedure("Bad Slug!")` run
  Then both return `None` and the second makes no repository call

Scenario: list order
  Given the repository holds slugs "tax-id" and "pesel", or none
  When `list_procedures()` runs
  Then it returns "pesel" then "tax-id", or an empty list

Scenario: store error
  Given the repository raises `ProcedureStoreError` from a lower error
  When `import_procedure(text)` runs as admin
  Then `ProcedureStoreError` propagates with `__cause__` set
