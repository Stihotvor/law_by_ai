# T1: Procedure models, errors and YAML parser (pure)

## Context
The bureaucracy assistant needs checked procedure data. A bad step can harm a user. This task builds the pure layer: models, errors and the parser. It serves the step-field, validation and schema-version rules in requirements.md.

## Technical Approach
Create `src/core/procedures/` with these files. The package imports only `core.security` and its own modules. It holds no SQL.
- `models.py`: frozen pydantic models with `extra="forbid"`.
  - `Step`: `key` (kebab-case), `text`, `source_url` (https only, no credentials, syntax check only), `last_checked` (date, not in the future), `verify_with_office` (non-empty).
  - `Procedure`: `schema_version`, `slug`, `title`, `steps` (at least 1, unique `key`, sorted by position), `revision` (set by the repository on read, not in the YAML).
  - `ProcedureSummary`: `slug`, `title`. `ImportResult`: `slug`, `revision`, `changed: bool`.
- `errors.py`: `ProcedureValidationError(source, step_key, reason)` and `ProcedureStoreError`. Messages hold no content.
- `parse.py`: `parse_procedure_yaml(text, today) -> Procedure`. Use `yaml.safe_load`. The clock is a parameter. Wrap YAML errors and pydantic errors into `ProcedureValidationError` that names the source and the step key.
- `__init__.py`: export the public names.
- Tests in `tests/unit/core/procedures/test_models_parse.py`. No network.

## Acceptance Criteria
Scenario: valid procedure parses
  Given a YAML text with 3 complete steps and a past `last_checked`
  When `parse_procedure_yaml(text, today)` runs
  Then it returns a `Procedure` with 3 steps in position order

Scenario: incomplete step is rejected
  Given a step with an empty `source_url`, or a missing `last_checked`, or no `verify_with_office`
  When the text is parsed
  Then `ProcedureValidationError` is raised and its `step_key` names that step

Scenario: future or invalid date is rejected
  Given a step with `last_checked` after `today`, or "not-a-date"
  When the text is parsed
  Then `ProcedureValidationError` is raised

Scenario: bad URL is rejected
  Given a `source_url` with `http://` or with `user:pw@` credentials
  When the text is parsed
  Then `ProcedureValidationError` is raised

Scenario: structure errors are rejected
  Given a procedure with zero steps, an unknown key, duplicate step keys, or malformed YAML
  When the text is parsed
  Then `ProcedureValidationError` is raised and its `source` is set

Scenario: schema is pinned
  Given the `Step` model and `schema_version`
  When the test reads `Step.model_fields` keys
  Then they equal exactly `key, text, source_url, last_checked, verify_with_office`, and the test pins the `schema_version` value
