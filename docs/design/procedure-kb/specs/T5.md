# T5: Three seed YAML files, seed script and run order doc

## Context
The assistant needs real procedures at first start. Three ship first: PESEL, residence card, tax ID. The owner reviews every source and step before merge. It serves the seed and idempotency rules in requirements.md.

## Technical Approach
- `data/procedures/pesel.yaml`, `residence-card.yaml`, `tax-id.yaml`: each has `schema_version`, `slug`, `title` and at least 3 steps. Each step has `key`, `text`, `source_url` (https), `last_checked` and `verify_with_office`. Wording follows ADR-0015: information, not advice. Only lawful procedures.
- `scripts/seed_db.py` (new): read `data/procedures/*.yaml`. Detect a duplicate slug before any write and stop with an error that names both files. Connect as `lawbyai_app` with `POSTGRES_URL`. Run inside `principal_context(RequestPrincipal(email="system:seed", role=ADMIN))` and call `ProcedureService.import_procedure` for each file. Errors name the file. The seed is idempotent.
- `docs/migrations.md`: state the run order, migrate then seed.
- Tests: `tests/unit/test_seed_procedures.py` (no network, no database: parse all files, count, steps, duplicate slug using temp files) and `tests/integration/test_seed_db.py` (real database, Docker suite).
- Content rule: the builder drafts each step only from an official source it has read (gov.pl, the Office for Foreigners, the tax office), through a research agent. Each `source_url` is a real page that was opened. `last_checked` is the date of that reading. The builder never fills a step from memory. The owner reviews every source and step in the PR.
- Owner gate: an approving owner PR review before merge. It is a process rule and no test proves it. The PR text states it and says the drafts were prepared by an AI from official sources.

## Acceptance Criteria
Scenario: exactly three seed files
  Given the directory `data/procedures/`
  When the unit test lists `*.yaml`
  Then there are exactly 3 files with slugs "pesel", "residence-card" and "tax-id"

Scenario: seed content is complete
  Given the 3 seed files
  When each is parsed with `parse_procedure_yaml`
  Then there are 0 errors, each has at least 3 steps, and every step has an https `source_url`

Scenario: bad seed file
  Given a temp file with an empty `source_url`
  When the seed runs on that directory
  Then it fails naming the file and writes nothing

Scenario: duplicate slug
  Given two temp files with the same slug
  When the seed runs
  Then it stops before any write and the error names both files

Scenario: seed twice
  Given a migrated empty database
  When the seed runs two times as `lawbyai_app`
  Then there are 3 procedures, 3 revision rows after the first run, and the same 3 after the second

Scenario: run order doc
  Given `docs/migrations.md`
  When the test reads it
  Then it contains the text of the order "migrate" before "seed"

## Definition of Done
- The task's `done_when` check passes: `tests/unit/test_seed_procedures.py` and `tests/integration/test_seed_db.py`.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
