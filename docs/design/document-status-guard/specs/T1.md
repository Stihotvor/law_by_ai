## Context
Any caller can set `status` to `approved` through `apply_update`, which writes every key that matches a model attribute. This task replaces that with a fixed allowlist. It serves the requirements that `update_document` and upsert never change `status`, and that the caller's dict stays unchanged.

## Technical Approach
- In `src/plugins/relational_db/mappers.py`, rewrite `apply_update` with a fixed map from payload key to model attribute: `title`, `content`, `source`, `source_url`, `is_processed` map to the same name, `metadata` maps to `metadata_`, `last_updated` goes through `parse_dt` to `last_updated`. Never call `setattr` with a payload key.
- `apply_update` returns the sorted names of the dropped keys, except `id`. Dropped keys include `status`, `tenant_id` and unknown keys.
- Do not change the input dict.
- `validate_status` stays in this task (T2 removes it with its callers). Keep the file importable.
- Rewrite the `ValueError` status tests in `tests/unit/plugins/test_postgres_status.py` as unit tests of `apply_update` with no database. Assert `row.metadata_` is set and `row.metadata` is still `Base.metadata`.

## Acceptance Criteria
Scenario: status is dropped
  Given a row with status "needs_review"
  When `apply_update(row, {"status": "approved", "title": "x"})` runs
  Then `row.status` equals "needs_review"
  And `row.title` equals "x"
  And the return value equals ["status"]

Scenario Outline: any status value is dropped
  Given a row with status "needs_review"
  When `apply_update(row, {"status": <value>})` runs
  Then `row.status` equals "needs_review"
  And the return value equals ["status"]
  And no error is raised
  Examples:
    | value      |
    | "approved" |
    | "bogus"    |
    | "rejected" |
    | ""         |
    | None       |

Scenario: tenant_id and unknown keys are dropped
  Given a row with tenant_id "t1"
  When `apply_update(row, {"tenant_id": "t2", "foo": 1})` runs
  Then `row.tenant_id` equals "t1"
  And the return value equals ["foo", "tenant_id"]

Scenario: id is ignored and not reported
  Given a row with id "d1"
  When `apply_update(row, {"id": "d2"})` runs
  Then `row.id` equals "d1"
  And the return value equals []

Scenario: allowed keys are copied
  Given a row
  When `apply_update` runs with title, content, source, source_url, is_processed, metadata and last_updated
  Then each value is set on the row
  And `row.metadata_` equals the metadata value
  And `row.metadata` is still `Base.metadata`
  And the return value equals []

Scenario: input dict is unchanged
  Given a payload dict with "status" and "title"
  When `apply_update(row, payload)` runs
  Then the payload equals its copy taken before the call
