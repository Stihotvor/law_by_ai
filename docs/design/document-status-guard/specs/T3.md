## Context
The fetch task is the only producer of documents. It sends `status = needs_review`, which the guard would now log as a dropped key. This task stops sending it and proves the ingest still saves a `needs_review` row. It serves the requirement that the fetch task keeps working and logs no status warning.

## Technical Approach
- In `src/tasks/fetch.py`, remove the `status` entry from `_to_document`. Remove the `DocumentStatus` import if it is then unused.
- In `tests/integration/test_fetch_task_integration.py`, add one test with production collaborators and a mock only at the network edge, like the existing tests. Use caplog for the warning check.
- Keep existing tests unchanged.

## Acceptance Criteria
Scenario: ingest stores needs_review
  Given a fetch of a new document with the network edge mocked
  When `fetch_document` runs
  Then the task returns status "saved"
  And the stored row has status "needs_review"

Scenario: ingest logs no status warning
  Given a fetch of a new document with the network edge mocked
  When `fetch_document` runs
  Then no warning that names "status" is logged

Scenario: payload has no status
  Given a fetched document
  When `_to_document(ref, fetched, text)` runs
  Then the returned dict has no "status" key

Scenario: payload with status approved is stored as needs_review
  Given a payload with status "approved" passed to `save_document` by the task path
  When the document is saved
  Then the stored row has status "needs_review"

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
