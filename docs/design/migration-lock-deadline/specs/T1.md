## Context
The Alembic run needs a typed deadline for the migration lock. This task adds the setting. It serves the requirement for a typed property read from `MIGRATION_LOCK_TIMEOUT_S` with default 300 and a start-time error for bad values.

## Technical Approach
- In `src/config/settings.py`, add `Settings.migration_lock_timeout_s`. Reuse `_positive("MIGRATION_LOCK_TIMEOUT_S", "300", float)`.
- Add unit tests in `tests/unit/config/test_settings.py`. Use monkeypatch for the environment variable.
- Test names contain `migration_lock_timeout`.
- Resolved: `_positive` names the variable in both errors ("must be a number", "must be positive and finite").

## Acceptance Criteria
Scenario: default value
  Given `MIGRATION_LOCK_TIMEOUT_S` is not set
  When `Settings().migration_lock_timeout_s` is read
  Then the value equals 300.0

Scenario: valid value
  Given `MIGRATION_LOCK_TIMEOUT_S` is "12.5"
  When `Settings().migration_lock_timeout_s` is read
  Then the value equals 12.5

Scenario Outline: invalid value
  Given `MIGRATION_LOCK_TIMEOUT_S` is "<value>"
  When `Settings().migration_lock_timeout_s` is read
  Then an error is raised
  And the error message contains "MIGRATION_LOCK_TIMEOUT_S"
  Examples:
    | value |
    | 0     |
    | -5    |
    | abc   |
