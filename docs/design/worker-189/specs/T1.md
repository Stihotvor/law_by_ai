# T1: module-level store and close handler

## Context
Each Celery prefork child builds one `PostgreSQLStore` but nothing closes it on exit. Idle connections stay open on a 4-6 GB host. This task serves the requirement to release connections at child exit and to fix the stale comment that says the store migrates (#209 moved migration to the `init` service).

## Technical Approach
Edit only `src/tasks/fetch.py`. Design P1 from `decision.md`.
- Remove `import functools`. Add `from celery.signals import worker_process_shutdown`.
- Add module-level `_store: PostgreSQLStore | None = None`.
- `_make_store()`: if `_store` is None, set `_store = PostgreSQLStore()`. Return it. A failed build (for example `SchemaNotAtHeadError`) leaves `_store` as None, so the next task retries. Call only inside a task.
- Add `_close_store(**_: object) -> None` with `global _store`, connected with `@worker_process_shutdown.connect`. If `_store` is None: return, build nothing. Else call `_store.close()` once inside `try`. On `Exception`, `_log.warning("store close failed", exc_info=True)`. In `finally`, set `_store = None`.
- Replace the stale comment: workers never migrate, the `init` service runs `alembic upgrade head`, and the store only checks the schema head.
- No change to `celery_app.py`, `fetch_document` signature, migrations or roles.

## Acceptance Criteria
```gherkin
Scenario: child with no store
  Given _store is None
  When the worker_process_shutdown signal is sent
  Then PostgreSQLStore is not called and _store is None

Scenario: child with a store
  Given _store holds a store
  When the worker_process_shutdown signal is sent
  Then store.close is called once and _store is None

Scenario: close raises
  Given _store holds a store whose close raises
  When the worker_process_shutdown signal is sent
  Then a warning with exc_info is logged, no exception escapes and _store is None

Scenario: failed build
  Given PostgreSQLStore() raises
  When _make_store is called
  Then the error propagates and _store is None

Scenario: stale comment
  When grep -n 'migrat' src/tasks/fetch.py runs
  Then no line claims that the store migrates
```
