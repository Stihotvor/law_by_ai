# T3: integration test on live PostgreSQL

## Context
Unit tests use mocks. They cannot prove that the real SQLAlchemy pool releases its connections. This task serves the success metric: after the handler runs, the old pool goes from more than 0 checked-in connections to 0.

## Technical Approach
Create `tests/integration/tasks/test_fetch_close_store.py`. Use production collaborators and live PostgreSQL. Mock nothing.
- Reset `tasks.fetch._store = None` before and after.
- Call `_make_store()`, run one query (for example a store read method), and save `old_pool = store._engine.pool`.
- Assert `old_pool.checkedin() > 0`.
- Send `worker_process_shutdown.send(sender=None)`.
- Assert `old_pool.checkedin() == 0`, `store._engine is None` and `tasks.fetch._store is None`. Do not assert `checkedout() == 0`: it cannot fail (architect review).
- Follow the fixtures and markers of the other tests in `tests/integration/`. The schema must be at head (the `init` service does this).

## Acceptance Criteria
```gherkin
Scenario: handler closes the live pool
  Given a store built by _make_store has run one query
  And old_pool = store._engine.pool has checkedin() > 0
  When worker_process_shutdown.send runs
  Then old_pool.checkedin() == 0
  And store._engine is None
  And tasks.fetch._store is None
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
