# T3: Document the advisory lock

## Context
Operators must know that overlapping upgrade runs wait, and why a run can seem stuck. Serves the failure modes in `requirements.md`.

## Technical Approach
Add one short section to `docs/migrations.md` with the word "advisory". Do not link to other docs. It states:
- Each online run takes a session-level `pg_advisory_lock` with key `0x6C61775F6D6967` ("law_mig"), so overlapping runs apply each migration once.
- A waiting run has no time limit. A hung run is visible in `pg_locks`.
- If a role or the server sets `lock_timeout` or `statement_timeout`, the waiting run fails with a timeout error.
- A dead process frees the lock because PostgreSQL ends its session. `--sql` mode takes no lock.
