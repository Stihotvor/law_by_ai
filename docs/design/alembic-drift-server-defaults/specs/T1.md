# T1: Add AUTOGEN_COMPARE_OPTS, use it in env.py and in the existing drift test

## Context
The drift test calls `compare_metadata` with no options, so Alembic 1.20.1 ignores server defaults. One shared options dict makes `env.py` and the test use the same rule. It serves the goal "catch a changed server default" and the constraint "test and env.py share one option source".

## Technical Approach
- Create `src/data/autogen.py` with `AUTOGEN_COMPARE_OPTS = {"compare_server_default": True}`. It is a plain dict with no Alembic import.
- In `migrations/env.py`, import the dict and spread it (`**AUTOGEN_COMPARE_OPTS`) into the online `context.configure`. Spread it into the offline call too, with a comment that this is for parity only, because autogenerate does not run offline.
- In `tests/integration/test_document_status_migration.py`, change `test_autogenerate_finds_no_changes` to call `MigrationContext.configure(conn, opts=AUTOGEN_COMPARE_OPTS)`. Keep `assert diff == []`.
- Do not edit any file in `migrations/versions/`.

## Acceptance Criteria
```gherkin
Scenario: Shared options in env.py
  Given the file migrations/env.py
  When grep searches it for AUTOGEN_COMPARE_OPTS
  Then both the online and the offline context.configure calls spread the dict

Scenario: No drift with server default comparison on
  Given a scratch database migrated to head
  When compare_metadata runs with opts=AUTOGEN_COMPARE_OPTS against Base.metadata
  Then the diff equals []

Scenario: Migrations stay unchanged
  Given the branch diff against main
  When git diff lists migrations/versions/
  Then it shows 0 changes
```
