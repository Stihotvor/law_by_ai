# T1: Add RequestPrincipal module and exports

## Context
The reject audit needs a trusted actor from the request, not a free argument. This task adds the principal context that the auth layer sets and the store reads. It serves the requirement that a caller cannot write another person's email, and the stale-actor failure mode.

## Technical Approach
Create `src/core/security/principal.py`, modelled on `src/core/security/tenant.py:37-85` (a `ContextVar` with `set`, `get`, `reset` and a restoring context manager).
- `@dataclass(frozen=True) RequestPrincipal(email: str, role: str)`. No `tenant_id`.
- `set_principal(p)`, `get_principal() -> RequestPrincipal | None`, `reset_principal()`.
- `principal_context(p)` context manager: restores the previous value in `finally`.
- `PrincipalRequiredError(PermissionError)`.
- `require_admin_principal() -> RequestPrincipal`: raise `PrincipalRequiredError` when the principal is None, the role is not `ADMIN` (`src/core/security/rbac.py:25`), or `email.strip()` is empty. Return a principal with the stripped email.
- Export the new names in `src/core/security/__init__.py` (imports at lines 22-41, `__all__` at 43-61) and add a "Principal" block to the module docstring.
- Import `ADMIN` from `.rbac`, not from the package, to avoid a cycle.
- Tests go in `tests/unit/core/security/test_principal.py`.

## Acceptance Criteria
```gherkin
Scenario: set, get and reset
  Given no principal is set
  When set_principal is called with an admin principal and then reset_principal is called
  Then get_principal returns the principal after set and None after reset

Scenario: context manager restores the previous value
  Given principal A is set
  When code runs inside principal_context(B) and raises an exception
  Then get_principal returns B inside the block and A after it

Scenario: missing principal is refused
  Given no principal is set
  When require_admin_principal is called
  Then it raises PrincipalRequiredError

Scenario: non-admin is refused
  Given a principal with role "user"
  When require_admin_principal is called
  Then it raises PrincipalRequiredError

Scenario: blank email is refused
  Given an admin principal with email "   "
  When require_admin_principal is called
  Then it raises PrincipalRequiredError

Scenario: admin passes with a stripped email
  Given an admin principal with email " a@x.pl "
  When require_admin_principal is called
  Then it returns a principal whose email is "a@x.pl"
```
