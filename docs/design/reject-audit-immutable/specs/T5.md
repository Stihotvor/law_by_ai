# T5: Owner-engine cleanup fixtures in three fetch integration tests

## Context
After T2 the app role cannot DELETE from `rejected_document`. Test cleanup that uses the app engine will fail with 42501. This is DBA fix F1. It serves the success metric that the Docker suite passes on the head schema.

## Technical Approach
Change the cleanup blocks to use an engine on `get_settings().postgres_owner_url`, as `tests/integration/plugins/test_postgres.py:32-33` does for TRUNCATE.
- `tests/integration/test_fetch_rejection.py:51`
- `tests/integration/test_fetch_worker_pool.py:60-63`
- `tests/integration/test_fetch_task_integration.py:68-71`
- Where one transaction deletes from `legal_document` and `rejected_document`, move the whole block to the owner engine. Dispose the engine after use.
- Any call to `reject(...)` in these files must drop the `admin` argument (T3) and run inside `principal_context`. Check each file for such calls.
- Depends on T1 and T3.

## Acceptance Criteria
```gherkin
Scenario: cleanup runs as owner
  Given the database is at the head schema
  When the three fetch test modules run in the Docker suite
  Then all tests pass with no 42501 error

Scenario: cleanup uses the owner URL
  Given the three modified fixtures
  When their source is read
  Then each DELETE on rejected_document runs on an engine created from postgres_owner_url
```
