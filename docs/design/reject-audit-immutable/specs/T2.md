# T2: Alembic revision to make rejected_document append-only for the app role

## Context
Today `lawbyai_app` can UPDATE and DELETE rows in `rejected_document` (granted by `b7e2d41c9a30`). The audit log must be immutable for the app role. This task adds the revision that removes those rights. It serves the business goal that only the owner can change or purge a row.

## Technical Approach
Add one file in `migrations/versions/` with `down_revision = "b7e2d41c9a30"`. Alembic runs it as `lawbyai_owner`. Follow the style of `b7e2d41c9a30` (grants at its line 285 per `decision.md`).
- upgrade: `SET LOCAL lock_timeout = '5s'`, then `REVOKE UPDATE, DELETE, TRUNCATE ON public.rejected_document FROM lawbyai_app`.
- downgrade: `SET LOCAL lock_timeout = '5s'`, then `GRANT UPDATE, DELETE ON public.rejected_document TO lawbyai_app`. Do not grant TRUNCATE, because `b7e2d41c9a30` never did.
- SELECT, INSERT and sequence grants stay.
- The docstring states the retention rule: rows are kept forever, and only the owner can fix or purge a row.
- Generate the id with `.venv/bin/alembic revision -m ...` and edit the file.
- Resolved: the parent is `migrations/versions/b7e2d41c9a30_harden_rls_tenant_only_policies.py`, the only head. The DBA verified that line 285 grants `SELECT, INSERT, UPDATE, DELETE` and no TRUNCATE.

## Acceptance Criteria
```gherkin
Scenario: upgrade removes write rights
  Given the database is at b7e2d41c9a30
  When the owner runs alembic upgrade head
  Then has_table_privilege('lawbyai_app','rejected_document','UPDATE') is false
  And the same check for DELETE and TRUNCATE is false
  And INSERT and SELECT are true

Scenario: single head
  Given the new revision file exists
  When alembic heads runs
  Then it lists exactly one head, the new revision

Scenario: downgrade restores the old rights
  Given the database is at the new head
  When the owner runs alembic downgrade -1
  Then UPDATE and DELETE are true for lawbyai_app and TRUNCATE is false
```
