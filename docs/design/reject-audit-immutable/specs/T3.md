# T3: PostgreSQLStore.reject(document_id) uses require_admin_principal

## Context
`reject` takes a free `admin` argument, so a caller can record any email (`src/plugins/relational_db/postgres.py:373`). The actor must come from the authenticated principal. This serves the requirement that the audit actor is the authenticated admin.

## Technical Approach
Edit `PostgreSQLStore.reject` in `src/plugins/relational_db/postgres.py:373-402`.
- Signature becomes `reject(self, document_id: str) -> None`. Remove `admin`.
- Import `require_admin_principal` from `core.security` (existing import at line 37).
- Call `principal = require_admin_principal()` first, before `_ensure_initialized()` and before any session opens.
- Write `admin=principal.email` in the `RejectedDocument` insert (line 398).
- Keep DELETE RETURNING and the insert in one `session.begin()` transaction, and keep the hook call after commit.
- Update the docstring: it raises `PrincipalRequiredError` (no principal, non-admin, blank email).
- Unit tests in `tests/unit/plugins/test_postgres_reject.py`: patch the engine or session, assert the error is raised before any session is created, and assert the signature has no `admin` parameter.
