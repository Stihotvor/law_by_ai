# T8: Quality gate

## Context
The repo requires a full quality gate before a task is done (project rules and CONTRIBUTING.md). This task runs it once on the finished branch. It serves the success metric that the gate passes with diff-cover at 90% or more.

## Technical Approach
Run from the repo root, with no code change. Fix failures in the task that caused them, not here.
- `.venv/bin/ruff check`, `.venv/bin/ruff format --check`, `.venv/bin/pyright`.
- `.venv/bin/pytest -m "not integration"`.
- Docker suite: `docker compose --profile test -f docker/docker-compose.yml run --rm test` after `build test`. It needs `docker/.env`. If a hook blocks `.env` access, the Docker suite is CI-only. Report that, do not skip it silently.
- diff-cover 90% or more on changed lines (see the "Coverage and mutation gates" section of CONTRIBUTING.md).

## Acceptance Criteria
```gherkin
Scenario: static checks
  Given T3 to T7 are done
  When ruff check, ruff format --check and pyright run
  Then each exits with code 0

Scenario: tests
  Given the static checks pass
  When the unit suite and the Docker suite run
  Then both exit with code 0

Scenario: coverage
  Given the test runs produced coverage data
  When diff-cover runs against main
  Then changed-line coverage is 90% or more
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
