# T2: PostgreSQLStore.insert_user, list_users and find_active_admin

## Context
The service needs a tenant-safe insert, list and actor lookup on the store. Email is unique across tenants, so a duplicate must map to one generic refusal. It serves the create and list goals and the leak-test metric.

## Technical Approach
In `src/plugins/relational_db/postgres.py` and `mappers.py` (signatures in the "Port signatures" section of `decision.md`):
- `mappers.py`: add `user_to_record(row: User) -> UserRecord`. Keep `user_to_dict` unchanged.
- `insert_user(self, *, email: str, password_hash: str, role: str, name: str) -> UserRecord`: take the tenant from `get_current_tenant()`. If empty, raise `PrincipalRequiredError` before any SQL. Insert the row with a new `uuid4` id, the given hash and `is_active = true`. Catch `IntegrityError` and map only SQLSTATE 23505 on constraint `uq_users_email` to `UserCreateRefusedError`. Re-raise any other error unmapped. Roll back on every error. No existence pre-check.
- `list_users(self) -> list[UserRecord]`: reuse the existing method. Change only the return annotation. Add a `tenant_id` predicate on top of RLS. Order by email. Return records without the hash. With no tenant set, return 0 rows.
- `find_active_admin(self, email: str) -> UserRecord | None`: compare the email exactly (the service normalises it). Filter on the current tenant, `role = 'admin'` and `is_active`. Return `None` for no match. With no tenant set, return `None` and run no SQL.
- `create_user` keeps its signature. The seed script still uses it.
- Tests in `tests/integration/test_store_users.py` on real Postgres.

## Acceptance Criteria
```gherkin
Scenario: Duplicate email gives the same error in any tenant
  Given a user with email "a@x.pl" exists in tenant A
  When tenant A inserts "a@x.pl" and tenant B inserts "a@x.pl"
  Then both calls raise UserCreateRefusedError with the same message

Scenario: Other integrity errors are not mapped
  Given an insert that breaks a constraint other than uq_users_email
  When insert_user runs
  Then the raised error is not UserCreateRefusedError

Scenario: List shows no foreign rows
  Given users exist in tenants A and B
  When tenant A calls list_users
  Then every returned row has tenant_id A, rows are ordered by email, and no row has a hash

Scenario: Actor lookup finds only an active admin of the tenant
  Given tenant A has an active admin, an inactive admin and an active user, and tenant B has an active admin
  When tenant A calls find_active_admin for each email
  Then only the active admin of tenant A is returned and every other call returns None

Scenario: No tenant set
  Given no current tenant
  When list_users runs
  Then it returns 0 rows
  And insert_user raises PrincipalRequiredError and no row is written
  And find_active_admin returns None
```
