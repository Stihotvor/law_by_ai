# T1: Service errors and UserRepository port

## Context
The user service (T4) and the store adapter (T2, T3) need shared error types and a port. This task creates both in `src/core/users/`. It serves the Path 2 decision and the business goal of create, list and deactivate.

## Technical Approach
- `src/core/users/errors.py`: define `UserCreateRefusedError`, `UserNotFoundError`, `SelfDeactivationError`, `LastAdminError`. `PrincipalRequiredError` stays in core security and is not redefined.
- `src/core/users/ports.py`: define the `UserRecord` TypedDict and the `UserRepository` Protocol, as in the "Port signatures" section of `decision.md`:
  - `UserRecord`: `id: str`, `tenant_id: str`, `email: str`, `role: str`, `name: str`, `is_active: bool`. No hash, no `session_version`.
  - `find_active_admin(self, email: str) -> UserRecord | None`
  - `insert_user(self, *, email: str, password_hash: str, role: str, name: str) -> UserRecord`
  - `list_users(self) -> list[UserRecord]`
  - `deactivate_user(self, user_id: str, *, actor_id: str) -> bool`
- Write the errors of each method in its docstring, as in `decision.md`.
- `src/core/users/__init__.py`: export the public names. Import only `core.security` and own modules. No `plugins.*`, no `streamlit`.
- Test file: `tests/unit/core/users/test_errors_ports.py`.

## Acceptance Criteria
```gherkin
Scenario: Errors are distinct types
  Given the four error classes in core.users.errors
  When a test raises each one
  Then each is caught only by its own class and is a subclass of Exception

Scenario: Package keeps its import boundary
  Given the module core.users
  When a test imports it and lists its imported modules
  Then no module starts with "plugins" or equals "streamlit"
```
