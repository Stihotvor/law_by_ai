# T5: Port and store conformance test

## Context
The port in core and the store adapter must not drift apart. A unit test compares them. It serves the decision's conformance requirement.

## Technical Approach
In `tests/unit/core/users/test_port_conformance.py`, use `inspect.signature` to compare each `UserRepository` method with the same method on `PostgreSQLStore` (parameter names, kinds, and defaults). Fail if the store lacks a method. Do not open a DB connection.

## Acceptance Criteria
```gherkin
Scenario: Signatures match
  Given the UserRepository port and PostgreSQLStore
  When the test compares each port method signature
  Then every method exists on the store with the same parameters

Scenario: Drift is detected
  Given a store method with a changed parameter name
  When the comparison helper runs on it
  Then the test reports a mismatch
```

## Definition of Done
- The task's `done_when` check passes: pytest tests/unit/core/users/test_port_conformance.py passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
