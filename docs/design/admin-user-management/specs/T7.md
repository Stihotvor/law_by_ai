# T7: Users Streamlit page

## Context
Admins need a UI to list, create and deactivate users. The page is a thin layer. It calls the service and maps errors to fixed messages. It serves the page-level requirements and edge cases.

## Technical Approach
- `src/ui/pages/users.py`: call `require_admin()` first. If it fails, show "Admin role required." and stop before any data loads. Wire `PostgreSQLStore` into the service here. Show the user list. Add a create form (email, name, role, password) with no tenant field. Add a deactivate action per row.
- Error map: `UserCreateRefusedError` shows "Cannot create this user." `UserNotFoundError`, `SelfDeactivationError`, `LastAdminError` and `PrincipalRequiredError` each show a fixed message. Any other exception shows a generic error with no stack trace and no raw text.
- `src/ui/app.py`: register the page in the same `is_admin` block as the fetch page.
- Tests in `tests/unit/ui/test_users_page.py` with a fake service. Follow the existing Streamlit page test pattern.

## Acceptance Criteria
```gherkin
Scenario: Role user opens the page
  Given a principal with role "user"
  When the page runs
  Then it shows "Admin role required." and the service is not called

Scenario: Duplicate email
  Given the service raises UserCreateRefusedError
  When the admin submits the create form
  Then the page shows "Cannot create this user."

Scenario: Database error
  Given the service raises a generic database error
  When the admin submits an action
  Then the page shows a generic message that has no traceback text

Scenario: Registration
  Given app.py with an admin principal and with a user principal
  When pages are registered
  Then the users page is present only for the admin
```
