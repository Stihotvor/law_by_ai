# T2: Unit tests for every public name in rbac.py

## Context
The MVP needs proof that RBAC rules fail closed. `src/core/security/rbac.py` has no unit test file. Every rule must have a test that fails when the rule is removed. Serves the Business Goals, Edge Cases and Success Metrics of requirements.md.

## Technical Approach
Create `tests/unit/core/security/test_rbac.py`. Test only the existing public API. Change no production code. Cover:
- Constants: `ADMIN == "admin"`, `USER == "user"`, `VALID_ROLES == {"admin", "user"}`.
- `is_admin`, `is_user`, `valid_role`: parametrized over `"admin"`, `"user"`, `""`, `"ADMIN"`, `"User"`, `" admin"`, `"root"`. Only exact lower-case values pass.
- `check_privilege_escalation`: admin with default required role returns `None`. `"user"` raises `PrivilegeEscalationError`. An unknown role (`""`, `"ADMIN"`, `"root"`) raises `PrivilegeEscalationError`, not `InvalidRoleError`. Pin this present behaviour. Assert `operation`, `requested_role`, `required_role` attributes and that the error is a `PermissionError`. Also test `required_role="user"` with role `"admin"` (raises, since the check is equality).
- `InvalidRoleError`: it is a `ValueError`, stores `.role`, message contains the repr of the role.
- `require_role`: default returns a predicate true only for `"admin"`. A custom `required` works. Unknown and empty roles give `False`.
- No design decision is open. `require_role` and `InvalidRoleError` stay as dead code covered only by tests (decision.md).

## Acceptance Criteria
```gherkin
Scenario: predicates fail closed on odd role strings
  Given the roles "", "ADMIN", "User", " admin" and "root"
  When is_admin, is_user and valid_role are called with each
  Then every call returns False

Scenario: predicates accept the exact roles
  Given the roles "admin" and "user"
  When is_admin, is_user and valid_role are called
  Then is_admin("admin") and is_user("user") are True and is_admin("user") is False
  And valid_role returns True for both

Scenario: a user cannot pass the admin check
  Given the role "user"
  When check_privilege_escalation("user") is called
  Then it raises PrivilegeEscalationError with requested_role "user" and required_role "admin"

Scenario: an unknown role raises PrivilegeEscalationError
  Given the role "root"
  When check_privilege_escalation("root") is called
  Then it raises PrivilegeEscalationError
  And it does not raise InvalidRoleError

Scenario: an admin passes the admin check
  Given the role "admin"
  When check_privilege_escalation("admin") is called
  Then it returns None

Scenario: require_role builds an equality predicate
  Given require_role() and require_role("user")
  When each predicate gets "admin", "user" and ""
  Then the default predicate is True only for "admin"
  And the "user" predicate is True only for "user"

Scenario: InvalidRoleError carries the role
  Given InvalidRoleError("x")
  When its attributes are read
  Then .role is "x" and it is a ValueError

Scenario: rbac.py is fully covered
  Given the new test file
  When pytest runs with --cov=core.security.rbac --cov-fail-under=100
  Then it exits 0
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
