# T5: Quality gate

## Context
This task checks the whole change before review. It serves the gate in `requirements.md` (Success Metrics). It depends on T3 and T4.

## Technical Approach
Run in order with the project tools in `.venv`: `ruff check`, `ruff format --check`, `pyright`, `pytest -m "not integration"`, then diff-cover on the changed lines (90% or more), then the Docker suite (`docker compose --profile test -f docker/docker-compose.yml run --rm test`, after `build test`). The CI mutation gate runs in CI only. Change no code. Report a failure to the owning task.
Resolved: the four new variables are bare compose keys with code defaults. An unset or empty value gives the default, so the local Docker suite needs no change to the local env file.

## Acceptance Criteria
```gherkin
Scenario: Static checks
  Given T1 to T4 are done
  When ruff check, ruff format --check and pyright run
  Then all three exit 0

Scenario: Fast tests and coverage
  Given the static checks pass
  When pytest -m "not integration" and diff-cover run
  Then pytest exits 0 and diff-cover reports 90% or more on changed lines

Scenario: Docker suite
  Given the image is rebuilt
  When the test service runs
  Then it exits 0 and test_fetch_document_worker_pool passes
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
