# T4: Compose and .env.example

## Context
The operator must be able to set the pool sizes through the Docker stack. It serves the requirement that the Streamlit pool is settable and the worker pool is configurable. It has no dependency.

## Technical Approach
- `docker/docker-compose.yml`: add bare keys `POSTGRES_POOL_SIZE:` and `POSTGRES_MAX_OVERFLOW:` to `x-app-env`. Add `WORKER_POSTGRES_POOL_SIZE:` and `WORKER_POSTGRES_MAX_OVERFLOW:` to the `celery-worker` environment. Do not touch `x-db-env` or `init`.
- `docker/.env.example`: add the four variables commented out with defaults (5, 10, 1, 1).
- The worker also gets the app pair through `x-app-env`. This is harmless: the worker reads only `WORKER_*`.

## Acceptance Criteria
```gherkin
Scenario: App and worker get the app pair
  Given the compose file
  When `docker compose -f docker/docker-compose.yml config` runs
  Then POSTGRES_POOL_SIZE and POSTGRES_MAX_OVERFLOW appear in app and celery-worker

Scenario: Worker pair only on the worker
  Given the same config output
  When the services are inspected
  Then WORKER_POSTGRES_POOL_SIZE and WORKER_POSTGRES_MAX_OVERFLOW appear in celery-worker

Scenario: Example file
  Given docker/.env.example
  When it is searched for the four names
  Then each name appears as a commented line with its default 5, 10, 1 or 1
```
