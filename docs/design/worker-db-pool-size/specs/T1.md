# T1: Settings pool config

## Context
The worker must open at most 4 connections and the app pool must be settable. This task adds the settings layer that T2 and T3 use. It serves the goals and the edge cases in `requirements.md` (reject size < 1, overflow < 0, non-integer, empty uses default).

## Technical Approach
In `src/config/settings.py`:
- Add `_int_at_least(name, default, minimum)`. Unset or empty returns `default`. A non-integer or a value below `minimum` raises `ValueError` that names the variable. The docstring says an empty value gives the default, unlike `_positive`. Do not change `_positive`.
- Add frozen dataclass `PoolConfig(size, max_overflow)`. `__post_init__` raises `ValueError` for `size < 1` or `max_overflow < 0`.
- Add properties `postgres_pool_size` (5, min 1), `postgres_max_overflow` (10, min 0), `worker_postgres_pool_size` (1, min 1), `worker_postgres_max_overflow` (1, min 0). Env names are `POSTGRES_POOL_SIZE`, `POSTGRES_MAX_OVERFLOW`, `WORKER_POSTGRES_POOL_SIZE`, `WORKER_POSTGRES_MAX_OVERFLOW`.
- Add `app_pool_config()` and `worker_pool_config()` that return a `PoolConfig`.
- Add the four variables to the module docstring table. Export `PoolConfig` in `__all__`.

Tests in `tests/unit/config/test_settings_pool.py` (use `monkeypatch.setenv` and `delenv`). At least 12 cases: default, valid override and rejected value for each of the 4 settings.

## Acceptance Criteria
```gherkin
Scenario: Defaults
  Given none of the four pool variables is set
  When app_pool_config() and worker_pool_config() are called
  Then app is PoolConfig(5, 10) and worker is PoolConfig(1, 1)

Scenario: Valid override
  Given WORKER_POSTGRES_POOL_SIZE is "2" and POSTGRES_MAX_OVERFLOW is "0"
  When the properties are read
  Then worker_postgres_pool_size is 2 and postgres_max_overflow is 0

Scenario: Empty value uses the default
  Given POSTGRES_POOL_SIZE is ""
  When postgres_pool_size is read
  Then it returns 5

Scenario Outline: Rejected value
  Given <name> is "<value>"
  When the matching property is read
  Then ValueError is raised and its message contains "<name>"
  Examples:
    | name                         | value |
    | POSTGRES_POOL_SIZE           | 0     |
    | POSTGRES_MAX_OVERFLOW        | -1    |
    | WORKER_POSTGRES_POOL_SIZE    | abc   |
    | WORKER_POSTGRES_MAX_OVERFLOW | -1    |

Scenario: PoolConfig validates itself
  Given a PoolConfig is built with size 0 or with max_overflow -1
  When __post_init__ runs
  Then ValueError is raised in both cases
```
