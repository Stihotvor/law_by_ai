# T3: Quality gate on the whole change

## Context
The project requires one gate before a task is done: ruff check, ruff format --check, pyright, pytest and diff-cover on changed lines. This task runs the gate on T1 and T2 together. It serves the gate metric in `requirements.md`.

## Technical Approach
Run the project tools from `.venv`, with `.venv/bin/python -m` where needed. Write no code. Fix findings only in files that T1 and T2 list, then run the gate again.
- `.venv/bin/ruff check`
- `.venv/bin/ruff format --check`
- `.venv/bin/pyright`
- `.venv/bin/pytest -m "not integration"`
- `.venv/bin/pytest -m "not integration" --cov=src --cov-report=xml`, then `uv run diff-cover coverage.xml --compare-branch=origin/main --fail-under=90`.
The CI mutation gate covers only `src/agents/fetch/`, so it does not apply. Docker integration tests are not part of this task.

## Acceptance Criteria
```gherkin
Scenario: Lint and format pass
  Given the branch with T1 and T2 applied
  When ruff check and ruff format --check run
  Then both exit 0

Scenario: Types pass
  Given the same branch
  When pyright runs
  Then it exits 0

Scenario: Fast tests pass
  Given the same branch
  When pytest -m "not integration" runs
  Then it exits 0

Scenario: Changed lines are covered
  Given the same branch and the coverage data of the fast tests
  When diff-cover compares with main
  Then the report shows 90% or more on changed lines
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
